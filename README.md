# Broadcast Pro · Multi Account

Telegram-сервис для управляемых рассылок от имени пользовательских Telegram-аккаунтов.

## Что умеет

- Любой пользователь бота может подключить свой Telegram-аккаунт.
- Вход прямо в боте: QR или номер телефона → код → 2FA при необходимости.
- Код входа вводится через inline-клавиатуру, а пароль 2FA удаляется сразу после проверки и не сохраняется.
- Telegram-сессии хранятся в PostgreSQL в зашифрованном виде.
- Каждый пользователь видит только свои аккаунты, получателей и кампании.
- У одного пользователя может быть несколько Telegram-аккаунтов.
- Получатели выбираются из групп и каналов, которые реально видит подключённый аккаунт.
- Контент кампании берётся из последнего сообщения/альбома в «Избранном» выбранного аккаунта.
- Можно отправить один раз, по конкретному времени или повторять каждые 15/30/60/120 минут либо задать свой интервал.
- Есть тест в Избранное, пауза, продолжение, остановка и статистика.
- FloodWait Telegram соблюдается — бот не пытается обходить ограничения платформы.

Используйте автоматизацию только в чатах и каналах, где такие сообщения разрешены.

## Railway variables

```env
BOT_TOKEN=
API_ID=
API_HASH=
DATABASE_URL=${{Postgres.DATABASE_URL}}
SESSION_SECRET=
TIMEZONE=Asia/Yekaterinburg
SEND_DELAY_SECONDS=2.0
WORKER_POLL_SECONDS=5
MAX_ACCOUNTS_PER_USER=5
MAX_TARGETS_PER_CAMPAIGN=100
MIN_REPEAT_MINUTES=15
LOG_LEVEL=INFO
```

`OWNER_IDS` можно оставить, но для обычных пользователей он больше не нужен: бот открыт для подключения собственных аккаунтов.

`USER_SESSION` больше не используется и его нужно удалить из Railway.

## API_ID / API_HASH

Это общие credentials Telegram-приложения сервиса. Получите их один раз на `my.telegram.org` → `API development tools` и положите в Railway. Пользователям бота свои API_ID/API_HASH вводить не нужно.

## SESSION_SECRET

Рекомендуется задать отдельный длинный случайный секрет, например 40–64 случайных символа. Он используется для шифрования сохранённых Telegram-сессий. Не меняйте его после запуска, иначе уже подключённые аккаунты потребуется подключить заново.

Если `SESSION_SECRET` пустой, ключ выводится из `BOT_TOKEN + API_HASH`, но отдельный секрет безопаснее и удобнее при ротации токена бота.

## Пользовательский сценарий

1. `/start` → `👤 Аккаунты` → `➕ Подключить аккаунт`.
2. Выбрать `QR` или `номер и код`.
3. После входа открыть аккаунт → `🎯 Чаты` → `➕ Добавить из моих чатов`.
4. Отметить группы/каналы.
5. Положить готовый пост/альбом в «Избранное» этого Telegram-аккаунта.
6. `📣 Новая рассылка` → выбрать аккаунт → `📥 Забрать последнее из Избранного`.
7. Выбрать получателей и режим времени.
8. При желании сделать `🧪 Тест в Избранное`.
9. Запустить кампанию. Её можно поставить на паузу, продолжить или остановить.

## Безопасность

- OTP-код не отправляется обычным сообщением: пользователь набирает его inline-клавиатурой.
- 2FA-пароль не сохраняется и входящее сообщение удаляется сразу после чтения.
- Сессионная строка Telethon шифруется перед записью в БД.
- При отключении аккаунта эта Telegram-сессия завершается через logout.
- Получателями могут быть только группы/каналы из диалогов самого подключённого аккаунта.
- Личные пользователи не используются как получатели рассылки.
